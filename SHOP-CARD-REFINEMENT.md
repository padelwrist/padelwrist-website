# Shop card refinement — 2 November 2026

## Final visual direction

The latest user review supersedes the intermediate image-left treatment. iPhone uses one stacked card per row: full-width rounded 2:1 contextual photograph, discreet illustrative disclaimer, explicit brand/category line, title, concise three-line summary, optional compact highlight chips, clearly labelled verified pack options and full-width disabled retailer action with supporting text. No image/caption side column remains. Accessibility sizes expand descriptions and use a full-width native menu instead of squeezing segmented options. Existing licensed 8:5 files are displayed with a consistent centred 2:1 crop; originals, hashes and permission evidence are unchanged.

The same structure is used on iPad and web. Native iPad uses two vertical cards per row, equal row heights and bottom-aligned controls; accessibility sizes become one column. Web uses one/two/three columns at phone/tablet/desktop widths. Context rows, title/summary space and flex footers align vertical cards. Category browsing remains prominent; phone web uses an accessible horizontal category rail. Players/Clubs controls fill the available content width with consistent outer margins.

Small verified variant families use native segmented selection (web: labelled radio chips), with full-width picker/menu controls for larger sets or native accessibility text sizes. Single variants stay simple. Selected IDs/indexes refer to the original verified variant records and exact original retailer URLs. No unverified options, prices, ratings, sales metrics or product photography have been added. Disabled View on Amazon buttons are actual disabled controls and still guard actions against unavailable destinations. Future native activation continues to require the binary-owned approval gate and approved marketplace/tracking IDs; remote metadata cannot activate it.

## Strict versioning and editorial controls

The existing strict v1/v2 contracts reject unknown product fields. Their generated bytes, endpoints and caches remain unchanged. `/catalogue/v3.json` retains v2 brands and introduces an optional `merchandising` object: two or three bounded original EN/ES `highlights`, one enumerated `badge` (`featured`/`editorsPick`) and/or one enumerated `suitability` (`beginner`/`intermediate`/`advanced`/`training`/`clubEssential`). Unknown keys, arbitrary badges, unsupported suitability, malformed/localisation omissions and prices/rating claims are rejected. Existing base product, URL, size, expiry, image and publication validation is reused.

The source-only `productMerchandising` register links original evidence URLs and independent EN/ES review status. Ordinary publication emits metadata only after **both** locales are approved. Suitability also requires an explicitly approved documented assessment; no suitability labels have been assigned. Current proposed highlights reuse recorded quantities, colour and backpack capacity; two proposed Featured badges are editorial ordering choices. All these new locale reviews remain **pending**. All existing product/family/commercial approvals remain pending and unchanged.

Pending proposed metadata is included only by `buildReviewCatalogueV3` in the existing isolated temporary review workflow, never by the Worker or public publisher. The normal 11-family / 13-ASIN review selection remains intact, with missing-highlights examples retained. PUSUN remains excluded and the Enhance grip SiteStripe exclusion hold remains. The ordinary v1/v2/v3 feeds contain zero products.

Native now defaults to v3 and `catalogue-v3-cache.json`, with endpoint/schema isolation and a categories-only bundled v3 fallback. It retains strict decoding and explicit-endpoint support for v1/v2; no migration, rename or overwrite of saved v1/v2 files occurs. Freshness, seven-day retention, expiry, ETag/304, bounded read and redirect/privacy policy are unchanged. No catalogue or cache is coupled to match data or purchases.

## Review and regression scope

- Native tests cover v3 optional metadata, independent legacy reading/cache files, invalid data rejection, the actual three child ASIN mappings and the unchanged mobile binary gate.
- Website tests cover EN/ES approval separately, suitability evidence, isolation of pending metadata, v1/v2 byte preservation, v3 endpoint/ETag/HEAD/schema mismatch and real variant mapping/disabled controls.
- Responsive audit covers EN/ES at 390/768/1440px, variant selection, brand/category filtering, no-results/reset, original-art recovery, disabled destinations and same-row footer alignment. Fixtures remain excluded from hosted assets and noindex.
- Simulator review uses isolated iPhone 17 and iPad Pro 11-inch (M5), iOS 27.0. Normal 11-product fixtures show short/long descriptions, single/multiple variants and absent highlights; a separate clearly labelled local stress fixture exercises long copy. Large accessibility text is reviewed without erasing user data. Full VoiceOver and physical-device checks remain separate release checks.

No production deployment, affiliate activation, product approval, merge, signing/version change or App Store upload is authorised. Activity, Events, scoring, History, Insights and entitlements are untouched.
