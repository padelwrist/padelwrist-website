# Shop card refinement — 2 November 2026

## Final visual direction

The latest user review supersedes the intermediate image-left treatment. iPhone uses one stacked card per row: full-width rounded contextual photograph, cropped to 140pt on compact widths, discreet illustrative disclaimer, explicit brand/category line, title, concise three-line summary, two compact evidence-backed checkmark highlights, clearly labelled verified pack options and full-width disabled retailer action with supporting text. No image/caption side column remains. Accessibility sizes expand descriptions and use a full-width native menu instead of squeezing segmented options. Existing licensed 8:5 files are displayed with a consistent centred crop; originals, hashes and permission evidence are unchanged.

The same structure is used on iPad and web. Native iPad uses two or three vertical cards per row where its measured content width permits, equal row heights and bottom-aligned controls; accessibility sizes become one column. Web uses one/two/three columns at phone/tablet/desktop widths. Context rows, title/summary space and flex footers align vertical cards. Category browsing remains prominent; phone web uses an accessible horizontal category rail. Players/Clubs controls fill the available content width with consistent outer margins.

Small verified variant families use native segmented selection (web: labelled radio chips), with full-width picker/menu controls for larger sets or native accessibility text sizes. Single variants stay simple. Selected IDs/indexes refer to the original verified variant records and exact original retailer URLs. No unverified options, prices, ratings, sales metrics or product photography have been added. Disabled View on Amazon buttons are actual disabled controls and still guard actions against unavailable destinations. Future native activation continues to require the binary-owned approval gate and approved marketplace/tracking IDs; remote metadata cannot activate it.

## Strict versioning and editorial controls

The existing strict v1/v2 contracts, generated bytes, endpoints and caches remain unchanged. `/catalogue/v3.json` retains v2 brands and adds optional bounded EN/ES short descriptions, two or three highlights and dynamic curated labels. A label has an editorial ID, independently localised text and optional audience scope. One suitability capsule is overlaid at the image's top-left with a solid navy/white treatment; secondary editorial badges remain outside the photograph. IDs and text are never inferred from names or mapped to hardcoded product copy. Unsupported sales, Amazon ranking, price and promotion claims are rejected.

The private `productMerchandising` registry records content, evidence URLs, independent EN/ES reviews and a documented suitability assessment. Both locale reviews must be approved before ordinary publication emits merchandising. Suitability requires either an explicitly approved assessment or an `evidenceRecorded` assessment tied to an existing ready-for-editorial-review evidence URL. Evidence recorded is not product approval. All 11 proposed locale reviews remain pending. Only the verified training bucket and bulk club format have scoped suitability proposals; no Beginner/Advanced labels were invented.

The private `productPresentation` registry supplies per-audience ordering, a complete ordered list of source variant IDs and a verified default variant ID. Publication exposes only verified published variants and safely falls back if the default is retired. Native and web use these remote values. Product review/publication/retirement, brands, categories, image licensing and exact original destination URLs remain in their established source records.

Editing workflow: edit `data/shop/catalogue.json`, attach evidence and review each language independently; adjust presentation order/defaults as needed; bump the catalogue revision when public output changes; generate HTML, Markdown and all versioned feeds with `node scripts/build-shop.mjs`; run catalogue, licensing, SEO and compatibility checks; review the draft PR. Deployment and commercial activation require separate approval. Supported content changes need no app release. The ordinary feeds still contain zero products. Pending metadata and the unchanged 11 families/13 ASINs appear only in isolated temporary fixtures produced by `build-shop-review.mjs`. PUSUN remains excluded and the Enhance grip SiteStripe hold remains.

Native now defaults to v3 and `catalogue-v3-cache.json`, with endpoint/schema isolation and a categories-only bundled v3 fallback. It retains strict decoding and explicit-endpoint support for v1/v2; no migration, rename or overwrite of saved v1/v2 files occurs. Freshness, seven-day retention, expiry, ETag/304, bounded read and redirect/privacy policy are unchanged. No catalogue or cache is coupled to match data or purchases.

## Review and regression scope

- Native tests cover v3 optional metadata, independent legacy reading/cache files, invalid data rejection, the actual three child ASIN mappings and the unchanged mobile binary gate.
- Website tests cover EN/ES approval separately, suitability evidence, isolation of pending metadata, v1/v2 byte preservation, v3 endpoint/ETag/HEAD/schema mismatch and real variant mapping/disabled controls.
- Responsive audit covers EN/ES at 390/768/1440px, variant selection, brand/category filtering, no-results/reset, original-art recovery, disabled destinations and same-row footer alignment. Fixtures remain excluded from hosted assets and noindex.
- Simulator review uses isolated iPhone 17 and iPad Pro 11-inch (M5), iOS 27.0. Normal 11-product fixtures show concise copy and single/multiple variants; separate stress fixtures exercise long descriptions and absent highlights; a separate clearly labelled local stress fixture exercises long copy. Large accessibility text is reviewed without erasing user data. Full VoiceOver and physical-device checks remain separate release checks.

No production deployment, affiliate activation, product approval, merge, signing/version change or App Store upload is authorised. Activity, Events, scoring, History, Insights and entitlements are untouched.
