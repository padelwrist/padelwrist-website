## Compatibility decision

Existing native and website v1 validators reject undeclared fields. Therefore the existing `/catalogue/v1.json` contract and generated bytes are unchanged. No redirect, renamed cache, extra brand field or replacement payload is sent to existing v1 clients. Its ETag/conditional serving and six-hour/seven-day cache behaviour are preserved.

The new `/catalogue/v2.json` has schemaVersion 2, a bounded `brands` array (`id`, `name`) and a required `brandID` on every product. Existing product, category, expiry, URL, image and publication rules are reused after removing the v2-only fields for v1 validation. Strict validators reject duplicate/unknown brands, missing mappings, unverified evidence, invalid text and unknown content fields. Brand identity is never derived from names/prefixes.

The private source has `editorialBrands` (stable ID, display name, identity verification date/evidence) and `productBrands` (explicit product-to-brand mapping). A new verified brand can be added editorially without changing an enum or releasing the app. Only brands referenced by publicly published products enter the ordinary v2 feed. This private metadata does not authorise products, photography or links.

The updated app reads strict v1 fixtures for compatibility and strict v2 for the new endpoint. Its default cache is `catalogue-v2-cache.json`; legacy `catalogue-v1-cache.json` is untouched. Cache records include endpoint identity and must match that endpoint's schema, so old/same-revision/late responses cannot cross versions. V2 failure uses the validated v2 saved/bundled collection, not an unverified migration of old data. Both bundled snapshots remain categories-only. Retention/expiry/ETag/network/redirect/privacy policy is unchanged.

## Browsing and cards

- Native has compact category and brand menus immediately above results, within one NavigationStack and without pushed category hierarchy. Menu selections have explicit accessible names/values and native checked options. Filters combine with the Players/Clubs audience and retain valid selections across tabs/refresh; audience changes clear only unavailable choices. Reset and no-results actions are in context. Accessibility text sizes stack controls vertically.
- Website has independent labelled brand/category controls per audience, actionable category artwork cards with pressed states, keyboard Space/Enter support, reset, live result counts and a no-results/reset state. Audience anchors retain clear sections and current-location styling. Product order is never altered by filtering. Without JavaScript, all product copy/variants remain readable in server-rendered HTML/Markdown; interactive controls are hidden rather than inert.
- Single variants remain simple labels. Multi-variant balls use pack-size selectors; future non-ball variants use “Option”. Original 8:5 category artwork remains the fallback. No Amazon/manufacturer photography, prices, stock, ratings or checkout is added.
- Existing typed analytics retain enum category/audience events only. Brand values are not added to native telemetry. Local/development hosts do not load website production analytics even with previously accepted consent; production consent behaviour is unchanged.
